## 🌟 Key Platform Features

1. **TryHackMe-Style Zero Friction Onboarding**:
   - Zero student registration, email verification, or password creation required.
   - Automatic cryptographically secure student session provisioning (`sess_<uuid>`) via HTTP-only, SameSite cookies.
   - Strict student session isolation: one student never sees another student's events, connection details, or challenge flags.

2. **Dedicated "My Connection Information" Panel**:
   - Live backend-detected incoming public IP address (never simulated or hardcoded).
   - Masked student session identifier.
   - Real-time client browser and user-agent detection.
   - Counter of real attack events generated by the student.
   - Single-click **Copy IP** button.
   - **SHOW MY ACTIVITY ONLY** filter toggle.

3. **Three Controlled Vulnerability Challenges (Dual-Stage Workflow)**:
   - **Stage 1 (Offensive)**: Execute exploit in the Attack Lab & obtain the **Attack Flag**.
   - **Stage 2 (Defensive)**: Triage the generated event in the SOC Dashboard / Event Explorer & uncover the **Investigation Flag**.
   - A challenge is only marked complete when both stages are validated.

4. **Production Enterprise SOC SIEM Telemetry Console**:
   - Real-time Server-Sent Events (SSE) telemetry stream pushing live attack events to the student's dashboard.
   - 550+ pre-seeded realistic synthetic baseline security events using RFC 5737 test IP pools (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`).
   - Clear visual differentiation:
     - `● MY ACTIVITY` (cyan glowing badge, student's real IP, `is_simulated: 0`)
     - `SIMULATED TRAINING DATA` (slate badge, documentation IPs, `is_simulated: 1`)
   - Severity breakdown donut chart & event category volume chart powered by Chart.js.
   - Deep forensic log inspector drawer revealing raw parameters, decodings, and hidden investigation flags.

## 💻 Local Development & Quickstart

### Prerequisites
- Node.js **v20.x or higher** (tested on Node v26)
- npm v10+

### Installation & Run

```bash
# 1. Clone the repository
git clone https://github.com/BlitzCyberLabs/cyberthreats_and_iocs.git
cd cyberthreats_and_iocs

# 2. Install dependencies
npm install

# 3. (Optional) Re-generate Word assessment documents
npm run generate-docs

# 4. Start the platform
npm start
```

Open your browser and navigate to:
```
http://localhost:3000
```

## 🌐 Production Deployment Guide

Because the platform uses a persistent backend, live SQLite database, and Server-Sent Events (SSE), it requires a Node.js hosting runtime (not static-only GitHub Pages).

### Option 1: Docker Deployment

Create a `Dockerfile`:
```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
ENV PORT=3000
ENV NODE_ENV=production
EXPOSE 3000
CMD ["npm", "start"]
```

Build and run:
```bash
docker build -t blitz-lab .
docker run -d -p 3000:3000 --name blitz-training-lab blitz-lab
```

### Option 2: Cloud PaaS (Render, Railway, Fly.io, DigitalOcean)

1. Connect your GitHub repository `BlitzCyberLabs/cyberthreats_and_iocs`.
2. Build Command: `npm install && npm run generate-docs`
3. Start Command: `npm start`
4. Set Environment Variables:
   - `NODE_ENV=production`
   - `PORT=3000`
   - `TRUST_PROXY=1`

### Option 3: Ubuntu / Debian VPS with Systemd & Nginx

```bash
# /etc/systemd/system/blitz-lab.service
[Unit]
Description=BLITZ Cyber Threats & IOC Investigation Lab
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/cyberthreats_and_iocs
ExecStart=/usr/bin/node server/server.js
Restart=on-failure
Environment=NODE_ENV=production PORT=3000 TRUST_PROXY=1

[Install]
WantedBy=multi-user.target
```

Nginx configuration with SSE buffering disabled:
```nginx
server {
    listen 80;
    server_name lab.blitzcyber.io;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Crucial for SSE live event streams:
        proxy_buffering off;
        proxy_cache off;
    }
}
```

## 🔒 Security Architecture

Although this platform intentionally hosts vulnerable training endpoints to teach exploitation and detection:
- **Sandbox Isolation**: The reflected XSS challenge runs inside an isolated iframe sandbox (`sandbox="allow-scripts"`), preventing arbitrary code execution from reaching student session cookies or dashboard state.
- **Controlled Mock Data**: Intentionally vulnerable SQLi and IDOR handlers execute against dummy training tables (`dummy_users`), ensuring zero risk to the underlying server or system configuration.
- **Session Privacy**: Student sessions are verified on every API call. Events and progress belonging to one student cannot be viewed or queried by another.
